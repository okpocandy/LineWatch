마지막 갱신: **2026-11-14, LW-04 완료 변경 분리 커밋**. 새 대화에서는 이 절과 아래 누적 이력을 먼저 읽는다. 이전 Starter 연결 완료 기록은 당시의 검증 이력이며 현재 구조는 이 절을 따른다. 최종 포트폴리오도 누적 이력과 실제 결과를 함께 확인한다.

### 현재 상태와 이어갈 위치

- 실제 Unity 프로젝트는 `D:\Unity_study\LineWatch`다. 대화의 현재 작업 폴더가 다른 곳이어도 이 경로를 대상으로 한다. Unity CLI 호출에는 해당 `--project-path`를 명시한다.
- Unity 6000.3.21f1 / URP 17.3.0 / realvirtual Starter 6.3.6 / Both 입력을 사용한다. 이미 끝낸 설치·제공 데모 검증은 반복하지 않는다. Urban 에셋은 사용하지 않는다.
- **LW-01~04 완료, LW-05 미착수**다. SCARA 자체 4축 구동·기준점·TCP 구성과 사용자 수동 확인을 마쳤다. FANUC는 자체 6축 수동 조작까지다. 다음은 SCARA FK다. FK·IK·피킹·관제·서버는 미구현이며 실제 버튼 클릭은 사용자에게 요청한다.
- `RobotLab.unity`에는 모델 계층을 재사용하는 독립 `ScaraRobot_Work` 프리팹과 `MachineControlLab` 시험 프리팹이 있다. Starter Drive·Sensor·Grip·PLC 신호·자동 피킹·씬 컨트롤러를 제거했다. 자체 `RotaryAxis`가 0↔30° 이동·중간 정지를 처리하고 `PresenceSensor`가 실제 Trigger 접촉을 감지한다. Play 진입만으로 자동 운전하지 않는다.
- FANUC A1~A6·제공 TCP·집게 모델을 유지하고 제공 동작 13개와 Rigidbody·Collider를 제거한 뒤, 자체 `RotaryAxis` 6개와 `FanucJointLab`을 연결했다. 상단 `LineWatch → FANUC 조작 테스트` 전용 창에서 축별 이동·정지·복귀와 전체 정지·복귀가 가능하다. 시험 범위는 모두 ±45°·20°/초이며 실물 사양이 아니다. FANUC FK·IK·집기·충돌 회피는 미구현이다. SCARA·시험 설비의 위치와 기존 조작은 유지한다.
- 자체 구현은 **Editor Play 세 세션·총 9회**를 새로 검증했다. 이동·중간 정지·복귀·센서 진입·이탈과 추가 경계 시험을 통과했고 Play 콘솔 오류는 0건이었다. 마지막 세션은 Collider 제거 처리 보완 후 검증이다. 새 `Builds/Windows-OwnCode/LineWatch.exe`는 빌드 성공(오류 0·기존 HDRP 참조 경고 2) 상태지만 **새 exe 실행·종료 검증은 실행 권한 요청 거절로 미완료**다. 초기 LW-02 실행 이력과 구분한다.
- 전체 정적 검사는 기존 Volume·Starter 자산의 오류 20건·경고 9건으로 여전히 미통과다. 자체 코드·작업 프리팹·RobotLab 관련 오류는 0건이다. 새 보고서는 `Logs/LW03-OwnCode/project-meta-audit.json`이며 전체 프로젝트 오류 0으로 설명하지 않는다.
- 조작은 **상단 `LineWatch → 조작 테스트` 별도 창 또는 MachineControlLab Inspector 상단 버튼**에서 수행한다. 축 각도·이동 상태·센서 점유·진입·이탈 횟수를 표시한다. Play 전·일시정지 중에는 버튼을 비활성화하고 안내한다. 사용자가 새 패널의 정상 동작을 직접 확인했다. 코드 독립 리뷰는 미확인이다.
- 과정 ②는 Play를 종료한 편집 상태에서 작업했다. 격리된 프리팹을 변경·저장한 뒤 새로 불러 기준 좌표를 검증했다. 기존 RobotLab 씬은 dirty=false, 시험 설비의 Axis1 참조 유지, 콘솔 오류 0건이었다. 네 축 이동 시험은 하지 않았다. 다음 Editor 작업 전 상태를 다시 확인한다.
- 이후 FANUC 추가에서도 저장·씬 재열기와 Play 검사를 통과했다. 두 모델·기존 SCARA 연결 유지, 씬 누락 스크립트 0, 원본 Starter 스크립트·프리팹 의존성 0, 실제 Play 콘솔 오류 0이다. 모델 표시·참조 검사이며 FANUC 이동 검증이 아니다. 검증 후 Play를 종료했다.
- 후속 자체 구동 검증에서 FANUC ±15° 이동 12건·중간 정지 6건·전체 정지·복귀·잘못된 목표 거부를 통과했다. SCARA·센서 회귀 3회도 통과했다. 전용 창 최종 컴파일을 확인했고 사용자가 패널을 직접 시험해 정상 동작을 보고했다. 향후 실제 버튼 클릭 테스트는 사용자에게 요청하며 AI가 직접 수행하지 않는다. 사용자 독립 코드 리뷰는 미확인이다.
- SCARA ③은 ±20° 회전·중간 정지·홈 복귀, 50mm 하강·정지·복귀·150mm 끝점, 전체 정지·복귀와 잘못된 목표 거부를 통과했다. 기존 단일 축·센서 3회 회귀와 FANUC 참조 유지도 확인했다. 메뉴·명령 버튼 14개·목표 입력 4개의 구성을 스크립트로 읽었고 직접 클릭하지 않았다. 이후 사용자가 새 패널 수동 테스트의 정상 동작을 확인해 LW-04를 완료 처리했다. 독립 코드 리뷰는 미확인이며 실제 TCP 표시를 FK 솔버 완료로 취급하지 않는다. 사용자의 수동 시험 후 Editor 상태는 다음 조작 전에 확인한다.
- 커밋 정리: 기존 LW-03은 `e44415e`이며 SCARA 4축·FANUC 6축 자체 조작·좌표계·검증 도구·문서를 LW-04로 묶어 별도 커밋한다. 기존 Windows 실행물에는 이번 변경이 포함되지 않는다. 푸시는 요청받지 않았다.

#### ② 손목·TCP 배치와 좌표 기준 — 2026-11-13

작업 프리팹의 기존 메시를 유지하고 다음 Transform을 추가했다. `RobotFrame`은 루트의 직속 자식이며 Axis1 홈 피벗과 같은 위치라 관절과 함께 회전하지 않는다.

```text
ScaraRobot_Work
├─ RobotFrame                 # 로봇 기준 원점: 루트 로컬 (0, 0.228, 0)m
└─ Base/Axis1/Axis2/Axis3
                     └─ Axis4    # 로컬 위치·회전 0, 새 손목 피벗
                         └─ Gripper
                             └─ TCP
```

**좌표 규칙:** 1 Unity unit = 1m. 내부 직선값·치수는 m, 회전은 도(°), 화면에서 mm를 표시할 경우 ×1000으로 변환한다. RobotFrame은 +Y 위쪽, 모델 홈에서 팔이 뻗는 방향이 +X다. +Y축 +90° 회전은 +X를 -Z로 보낸다. 로봇 루트는 단위 스케일을 유지한다.

| 관절 | 종류·양의 방향 | 홈 명령값 | 과정 ③에서 적용할 시뮬레이션 범위 |
|---|---|---|---|
| q1 / Axis1 | 로컬 +Y 회전, 홈 회전에 상대적으로 적용 | 0° | -170°~+170°; 현재 단일 축 시험 설정을 유지 |
| q2 / Axis2 | 로컬 +Y 회전, Axis1에 상대적인 관절각 | 0° | -150°~+150° |
| q3 / Axis3 | 아래로 내려갈수록 양수. `homeLocalPosition - Vector3.up * q3` | 0m (위쪽 기준) | 0~0.15m (150mm 스트로크 초안) |
| q4 / Axis4 | 로컬 +Y 회전, Axis3에 상대적인 손목각 | 0° | -180°~+180° |

이 범위는 실물 사양·충돌 회피·안전 인증에서 얻은 값이 아니다. 소프트웨어 시험을 위한 설계 초안이며 전체 범위의 간섭·동작 검증은 아직 하지 않았다. q2=0인 홈은 완전 신장한 기하학적 영점이다. 실제 피킹 대기 자세와 특이 자세 처리는 후속 단계에서 별도로 정한다.

**TCP 규칙:** 가상 흡착 집게의 하단 중심을 이 프로젝트의 접촉 기준점으로 정한다. 원본 메시 bounds의 하단 중심을 사용한 설계 선택이며 실물 공구 교정값이 아니다. Gripper 로컬 위치는 `(0, -0.027277, 0)m`, 로컬 Y 회전은 -90°다. Axis3의 모델 홈 회전 +90°와 상쇄되어 모든 명령값이 0일 때 TCP의 방향이 RobotFrame과 같아진다. 접근 방향은 TCP의 -Y다. 모델 메시와 Gripper의 기존 홈 회전은 변경하지 않았다.

- 홈 TCP 좌표: RobotFrame 기준 약 `(0.700000, -0.115177, 0)m`, 수평 회전 0°. 도구 오프셋은 Axis3 기준 Y 약 -0.034177m이며 링크 높이 오프셋과 분리한다.

- 자동 검증: 6축 각각 +15°·-15° 이동 12건, 중간 정지 6건, 홈 복귀·잘못된 목표 거부, 전체 정지·복귀를 통과했다. 보고서상 각 축의 목표·홈 실제 회전 오차와 정지 후 변화는 0°다. 실제 TCP도 각 단독 회전에 약 15°로 반응했고 다른 관절의 로컬 홈 회전은 유지됐다. 테스트한 소규모 각도 밖의 전체 범위나 충돌 안전성을 검증한 결과가 아니다.
- 회귀: 공유 RotaryAxis 변경 후 기존 `VerifyMachineControl`의 SCARA·센서 3회 시험을 통과했다. 저장·재열기 검사는 FANUC 자체 축 6개·TCP 연결, 기존 SCARA 기준점·시험 연결, 누락 스크립트와 원본 코드 비의존을 확인했다.
- 정적 검사: 5,207개 파일에서 기존 오류 20건·경고 9건이 남아 전체 미통과다. 자체 코드·작업 씬·프리팹에 해당하는 오류는 0건이며 새 보고서는 `Logs/FanucJoints/project-meta-audit.json`이다.
- UI 확인: 창 크기 조정에서 현재 Unity API의 void 반환을 잘못 사용해 컴파일 오류가 발생했고 해당 코드를 제거했다. 이후 전용 EditorWindow로 구현해 최종 컴파일을 통과했다. AI의 화면 조작은 Esc로 중단됐으며 실제 버튼 클릭 확인 완료로 기록하지 않는다. 후속 사용자 메시지에서 새 패널을 직접 시험해 잘 작동한다고 확인했으므로 수동 확인 완료로 기록한다. 독립 코드 리뷰 완료를 뜻하지 않는다.
- 근거: `Tools/Verification/VerifyFanucJoints.cs`, `Logs/FanucJoints/configuration.json`, `verification-20261113-142029.json`; SCARA 회귀 `Logs/LW03-OwnCode/verification-20261113-142058.json`; 저장 연결 `Logs/RobotModels/verification-joints-editor.json`. 좁은 Inspector가 잘린 초기 캡처는 최종 UI 근거로 사용하지 않고 정리했다.
- 기여·남은 범위: 사용자는 새 패널의 수동 동작을 확인하고 향후 수동 클릭 시험의 담당을 지정했다. AI는 코드·설정·자동 검증·문서를 수행했다. FANUC FK·IK·공구 위치 목표·충돌 회피·집기와 SCARA LW-04 과정 ③은 아직 남아 있다. 기존 Windows 빌드를 최신 기능으로 재빌드하지 않았으며 커밋·푸시는 하지 않았다.

## 작업을 끝낼 때 남길 것

각 작업은 체크박스만 채우지 않고 다음을 짧게 남긴다.

1. 바뀐 씬·프리팹·스크립트와 본인이 구현한 부분.
2. 완료 기준을 검증한 방법과 결과. 숫자는 실제 측정값을 사용한다.
3. 해결하지 못한 문제와 다음 작업을 막는 조건.
4. 사용자 요청으로 커밋했다면 실제 해시와 한국어 제목을, 하지 않았다면 미커밋 상태를 기록한다. 커밋·푸시는 사용자 요청 없이 진행하지 않는다.

경계가 명확한 FK·IK와 상태 전이는 자동 검증을 활용하고, 선택·카메라·집기·화면 반영은 실행 중 동작으로 확인한다. 테스트를 만드는 것 자체를 목표로 삼지 않는다.

**수동 테스트 담당 — 2026-11-13 사용자 지침:** 실제 화면에서 조작 패널 버튼을 누르는 테스트는 사용자가 수행한다. AI는 해당 클릭 테스트를 직접 수행하지 않고, 컴파일·스크립트 자동 검증 후 사용자에게 조작 순서와 예상 결과를 안내한다. 사용자가 확인한 결과를 자동 검증과 구분해 README·누적 이력에 기록한다.

### LW 완료 후 포트폴리오 기록

이 기준은 LineWatch 작업에만 적용한다.

- 각 LW를 마칠 때 포트폴리오에 설명할 가치가 있는 설계 판단, 문제 해결, 재현 가능한 검증이나 측정 결과가 있으면 README의 관련 사례를 추가·갱신한다.
- 제약 또는 문제, 선택한 방법과 이유, 검증 근거와 실제 결과, 남은 한계를 짧게 연결해 작성한다. 기존 설명과 겹치면 새 절을 늘리기보다 해당 내용을 갱신한다.
- 사용자 직접 작업, AI 작성·검증 작업, Starter 제공 기능을 구분하고 구현 예정과 완료 상태를 명시한다. 확인하지 않은 개인 기여·검토 완료·성과 수치는 작성하지 않는다.
- 단순 파일 이동·기본 배치·반복 설치 등 설명 가치가 작으면 포트폴리오 사례를 억지로 추가하지 않는다. 작업 상태와 완료 근거는 이 체크리스트에 남긴다.

### 대화가 바뀌어도 유지할 기록

- 각 LW 완료 또는 대화 종료 시점에 위 '새 대화 인수인계'의 현재 단계·다음 작업·미해결 사항·Git 상태를 갱신한다. 같은 내용을 별도 인수인계 파일로 늘리지 않는다.
- '기여와 검증 누적 이력'에 날짜·작업 ID·사용자 직접 작업 또는 결정·AI 작성/실행 작업·증거·미확인 항목을 추가한다. 기존 기록을 후속 작업으로 덮어쓰지 않는다. 이전 기록에 오류가 있으면 정정 이유를 남긴다.
- 사용자 수동 검증, AI 자동 검증, 제공 에셋 기능을 구분한다. 사용자의 지시·승인은 사용자 결정으로 기록하고, AI가 작성·실행한 코드를 사용자가 직접 작성·검증한 것으로 바꾸지 않는다.
- 실제 생성·확인한 보고서 경로와 측정값, 실행 환경(Editor/빌드), 커밋 해시를 남긴다. 파일이 없는 경우 이전 기록과 새 재현 결과를 구분하고, 확인하지 않은 수치를 채우지 않는다.
- 최종 대화에서는 누적 이력·README 역할 분담·단계별 완료 기록을 대조해 포트폴리오를 정리한다. 현재 완료 기능과 예정 기능, 사용자가 직접 설명·재현한 범위와 아직 미확인인 범위를 함께 확인한다.

## 범위를 지키는 기준

- 여러 기종을 다루되 기종별 관절 기준과 자체 구동 검증을 구분한다. 현재 FANUC는 자체 수동 관절 조작까지이며 SCARA의 4축 구성·물류 셀 구현과 완료 여부를 분리한다. 여러 셀 부하는 성능 검증 단계에서 늘린다.
- 4축 IK와 정해진 경유점 피킹부터 완성한다. 6축 자세 제어·충돌 회피 경로 계획은 후속 과제다.
- 실물 PLC 없이도 외부 서버와의 실제 통신을 구현한다. 가상 데이터 사용 여부를 명시한다.
- 상세 화면 꾸미기와 차트는 정확한 상태·수량·알람 연결 후 진행한다.
- 대기열로 발생한 정상 대기는 적체 고장과 구분한다.
- 상품 수량, 축 단위, 도구 오프셋, 상태 전이가 맞지 않으면 다음 큰 기능으로 넘어가지 않는다.
- 업체 패키지·샘플·유료 에셋 원본은 공개하지 않는다. 자체 코드·설정·문서의 공개 범위를 확인한다.
