## 진행 순서

**작업 기반(01~03) → 로봇 FK·IK(04~08) → 물류 셀과 피킹(09~12) → 관제·고장 대응(13~15) → 외부 연동(16~18) → 검증·최적화·제출(19~22)**

위 순서대로 하나씩 진행한다. 특히 LW-07에서 IK 경계 처리가 확인되기 전에는 로봇이 연결된 전체 라인이나 관제 화면을 크게 확장하지 않는다. 외형 꾸미기는 마지막 기능 통합 후 진행한다.

- RobotLab 씬을 만들고 카메라와 바닥을 배치한다.
- Starter의 ScaraRobot을 작업 인스턴스로 가져와 구조를 살펴본다. 직접 조정할 설정은 본인 프리팹에 저장한다.
- 자체 C# 코드는 Assets/02.Scripts/LineWatch 아래에 둔다. 기능 폴더는 실제 코드가 생길 때 만든다.
- 패키지 원본과 제공 피킹 로직이 자체 제어와 동시에 관절을 쓰지 않도록 확인한다.
- 완료 확인: 씬을 닫았다 다시 열어 모델과 참조가 유지되는지 확인한다. 아직 IK나 전체 관제 UI를 만들지 않는다.

### LW-02: 작은 상태에서 빌드 확인하기

- 빌드 대상에는 자체 작업 씬을 넣는다.

#### LW-02 완료 기록 — 2026-11-11

- 구성: 공유 빌드 씬 목록의 사라진 mainScene 및 FPS 데모 항목을 제거하고 `Assets/01.Scenes/RobotLab.unity` 하나만 활성화했다. Windows x64, 기존 Mono 백엔드로 일반 빌드(Development 옵션 없음)를 생성했다. 별도의 런타임 코드는 추가하지 않았다.
- 결과: `Builds/Windows/LineWatch.exe` 생성 성공, 빌드 시간 124.983초, BuildReport 크기 175,519,640바이트, 오류 0건·경고 7건이다. 실행에는 exe뿐 아니라 Data·UnityPlayer.dll·MonoBleedingEdge 등 빌드 폴더 전체가 필요하다.
- 실행 검증: Editor Play 모드를 사용하지 않고 exe를 직접 실행했다. 실제 Windows 창에서 SCARA·지지대·바닥·조명 및 카메라 화면을 확인했고 Player.log에서 RobotLab 시작을 확인했다. 화면 자동화 중단 후 정상 종료는 사용자가 Alt+F4로 직접 확인했다. 후속 검사에서 LineWatch 프로세스 0개, 종료 후 Player.log의 예외 및 리소스 로딩·셰이더 오류 검색 결과 0건을 확인했다. 종료 코드는 별도로 측정하지 않았다.
- 경고: Starter 원본의 C# 경고 5건(CS0109 2건, CS0414 3건)과 미설치 HDRP 관련 제공 리소스의 누락 스크립트 경고 2건이다. URP RobotLab 실행을 막지 않았으며 패키지 원본은 수정하지 않았다.
- 증거: `Logs/LW02/build-report.json`, 종료 후 복사한 `Logs/LW02/Player.log`를 남겼다. Builds와 Logs는 Git 제외 대상이다. 빌드 검증용 자동 tick은 해제했다. 빌드 과정에서 자동 갱신된 URP·Volume·Player 및 UnityConnect 설정 파일도 검증 결과와 함께 버전 관리한다.
- 남은 사항: LW-02 완료 기준을 충족했다. 후속 사용자 요청에 따라 `LW-02: 빌드 검증과 SCARA 로직 분석 정리` 한국어 메시지로 로컬 커밋한다. LW-03 자체 C# Drive·Sensor 연결은 사용자 요청 전까지 진행하지 않으며 푸시하지 않는다.

### LW-03: 프레임워크를 코드로 다뤄보기

- Drive 하나의 목표값을 코드에서 바꾸고 실제 이동과 정지를 관찰한다.
- Sensor 안으로 물체를 넣었다 빼면서 감지 결과를 읽는다.
- Starter의 현재 버전 API와 단위를 확인해 사용한다. 외부 문서의 코드가 그대로 맞는다고 가정하지 않는다.
- 이 단계에서는 임시 관제 화면이나 서버를 만들지 않는다. 이후 로봇과 라인 제어에 필요한 연결만 확인한다.

## 작업을 끝낼 때 남길 것

각 작업은 체크박스만 채우지 않고 다음을 짧게 남긴다.

1. 바뀐 씬·프리팹·스크립트와 본인이 구현한 부분.
2. 완료 기준을 검증한 방법과 결과. 숫자는 실제 측정값을 사용한다.
3. 해결하지 못한 문제와 다음 작업을 막는 조건.
4. 해당 변경을 구분할 수 있는 한국어 Git 커밋. 예: LW-06: SCARA 해석적 역기구학 구현.

경계가 명확한 FK·IK와 상태 전이는 자동 검증을 활용하고, 선택·카메라·집기·화면 반영은 실행 중 동작으로 확인한다. 테스트를 만드는 것 자체를 목표로 삼지 않는다.

## 범위를 지키는 기준

- 로봇 한 대와 셀 하나를 먼저 완성한다. 여러 셀은 성능 검증 단계에서 늘린다.
- 4축 IK와 정해진 경유점 피킹부터 완성한다. 6축 자세 제어·충돌 회피 경로 계획은 후속 과제다.
- 실물 PLC 없이도 외부 서버와의 실제 통신을 구현한다. 가상 데이터 사용 여부를 명시한다.
- 상세 화면 꾸미기와 차트는 정확한 상태·수량·알람 연결 후 진행한다.
- 대기열로 발생한 정상 대기는 적체 고장과 구분한다.
- 상품 수량, 축 단위, 도구 오프셋, 상태 전이가 맞지 않으면 다음 큰 기능으로 넘어가지 않는다.
- 업체 패키지·샘플·유료 에셋 원본은 공개하지 않는다. 자체 코드·설정·문서의 공개 범위를 확인한다.
