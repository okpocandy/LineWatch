## 새 대화 인수인계

마지막 갱신: **2026-11-13, 자체 코드·에디터 조작 패널 사용자 확인 및 커밋 정리**. 새 대화에서는 이 절과 아래 누적 이력을 먼저 읽는다. 이전 Starter 연결 완료 기록은 당시의 검증 이력이며 현재 구조는 이 절을 따른다. 최종 포트폴리오도 누적 이력과 실제 결과를 함께 확인한다.

### 현재 상태와 이어갈 위치

- 실제 Unity 프로젝트는 `D:\Unity_study\LineWatch`다. 대화의 현재 작업 폴더가 다른 곳이어도 이 경로를 대상으로 한다. Unity CLI 호출에는 해당 `--project-path`를 명시한다.
- Unity 6000.3.21f1 / URP 17.3.0 / realvirtual Starter 6.3.6 / Both 입력을 사용한다. 이미 끝낸 설치·제공 데모 검증은 반복하지 않는다. Urban 에셋은 사용하지 않는다.
- **초기 LW-01~03 완료 후 자체 코드로 전환, LW-04 미착수**다. 에셋은 모델·UI 등 표현에 활용하며 구동·감지·이송·생성·집기·진행은 프로젝트 코드로 구현한다. 현재 모델은 3개 관절 계층이며 자체 제어는 Axis1 하나뿐이다. 4축·FK·IK·자동 피킹·관제·서버는 아직 구현하지 않았다.
- `RobotLab.unity`에는 모델 계층을 재사용하는 독립 `ScaraRobot_Work` 프리팹과 `MachineControlLab` 시험 프리팹이 있다. Starter Drive·Sensor·Grip·PLC 신호·자동 피킹·씬 컨트롤러를 제거했다. 자체 `RotaryAxis`가 0↔30° 이동·중간 정지를 처리하고 `PresenceSensor`가 실제 Trigger 접촉을 감지한다. Play 진입만으로 자동 운전하지 않는다.
- 자체 구현은 **Editor Play 세 세션·총 9회**를 새로 검증했다. 이동·중간 정지·복귀·센서 진입·이탈과 추가 경계 시험을 통과했고 Play 콘솔 오류는 0건이었다. 마지막 세션은 Collider 제거 처리 보완 후 검증이다. 새 `Builds/Windows-OwnCode/LineWatch.exe`는 빌드 성공(오류 0·기존 HDRP 참조 경고 2) 상태지만 **새 exe 실행·종료 검증은 실행 권한 요청 거절로 미완료**다. 초기 LW-02 실행 이력과 구분한다.
- 전체 정적 검사는 기존 Volume·Starter 자산의 오류 20건·경고 9건으로 여전히 미통과다. 자체 코드·작업 프리팹·RobotLab 관련 오류는 0건이다. 새 보고서는 `Logs/LW03-OwnCode/project-meta-audit.json`이며 전체 프로젝트 오류 0으로 설명하지 않는다.
- 조작은 **상단 `LineWatch → 조작 테스트` 별도 창 또는 MachineControlLab Inspector 상단 버튼**에서 수행한다. 축 각도·이동 상태·센서 점유·진입·이탈 횟수를 표시한다. Play 전·일시정지 중에는 버튼을 비활성화하고 안내한다. 사용자가 새 패널의 정상 동작을 직접 확인했다. 코드 독립 리뷰는 미확인이다.
- 이전 자동 검증은 편집 상태로 복원했으나 이후 사용자의 수동 Play 테스트가 이어졌다. 새 대화에서 Editor를 조작하기 전 Play·일시정지·자동 tick 상태를 다시 확인한다. 직전 시험 시간 초과는 사용자가 직접 일시정지한 상태였음을 확인했다.
- 사용자 요청으로 LW-03·자체 코드 전환·에디터 패널·관련 문서를 이번 커밋에 묶는다. 기반 커밋은 `e2a889e`이며 새 해시는 `git log -1`로 확인한다. 기존 `Assets/codex.cs`→`Assets/02.Scripts/codex.cs` 이동은 별도 미커밋 변경으로 보존하고 이번 커밋에서 제외한다. 시험 코드·프리팹 이름 변경 시 `.meta` GUID를 유지했다. 푸시는 요청받지 않았다.

## 작업을 끝낼 때 남길 것

각 작업은 체크박스만 채우지 않고 다음을 짧게 남긴다.

1. 바뀐 씬·프리팹·스크립트와 본인이 구현한 부분.
2. 완료 기준을 검증한 방법과 결과. 숫자는 실제 측정값을 사용한다.
3. 해결하지 못한 문제와 다음 작업을 막는 조건.
4. 사용자 요청으로 커밋했다면 실제 해시와 한국어 제목을, 하지 않았다면 미커밋 상태를 기록한다. 커밋·푸시는 사용자 요청 없이 진행하지 않는다.

경계가 명확한 FK·IK와 상태 전이는 자동 검증을 활용하고, 선택·카메라·집기·화면 반영은 실행 중 동작으로 확인한다. 테스트를 만드는 것 자체를 목표로 삼지 않는다.

### LW 완료 후 포트폴리오 기록

이 기준은 LineWatch 작업에만 적용한다.

- 각 LW를 마칠 때 포트폴리오에 설명할 가치가 있는 설계 판단, 문제 해결, 재현 가능한 검증이나 측정 결과가 있으면 README의 관련 사례를 추가·갱신한다.
- 제약 또는 문제, 선택한 방법과 이유, 검증 근거와 실제 결과, 남은 한계를 짧게 연결해 작성한다. 기존 설명과 겹치면 새 절을 늘리기보다 해당 내용을 갱신한다.
- 사용자 직접 작업, AI 작성·검증 작업, Starter 제공 기능을 구분하고 구현 예정과 완료 상태를 명시한다. 확인하지 않은 개인 기여·검토 완료·성과 수치는 작성하지 않는다.
- 단순 파일 이동·기본 배치·반복 설치 등 설명 가치가 작으면 포트폴리오 사례를 억지로 추가하지 않는다. 작업 상태와 완료 근거는 이 체크리스트에 남긴다.

### 대화가 바뀌어도 유지할 기록

- 각 LW 완료 또는 대화 종료 시점에 위 '새 대화 인수인계'의 현재 단계·다음 작업·미해결 사항·Git 상태를 갱신한다. 같은 내용을 별도 인수인계 파일로 늘리지 않는다.
- '기여와 검증 누적 이력'에 날짜·작업 ID·사용자 직접 작업 또는 결정·AI 작성/실행 작업·증거·미확인 항목을 추가한다. 기존 기록을 후속 작업으로 덮어쓰지 않는다. 이전 기록에 오류가 있으면 정정 이유를 남긴다.
- 사용자 수동 검증, AI 자동 검증, 제공 에셋 기능을 구분한다. 사용자의 지시·승인은 사용자 결정으로 기록하고, AI가 작성·실행한 코드를 사용자가 직접 작성·검증한 것으로 바꾸지 않는다.
- 실제 생성·확인한 보고서 경로와 측정값, 실행 환경(Editor/빌드), 커밋 해시를 남긴다. 파일이 없는 경우 이전 기록과 새 재현 결과를 구분하고, 확인하지 않은 수치를 채우지 않는다.
- 최종 대화에서는 누적 이력·README 역할 분담·단계별 완료 기록을 대조해 포트폴리오를 정리한다. 현재 완료 기능과 예정 기능, 사용자가 직접 설명·재현한 범위와 아직 미확인인 범위를 함께 확인한다.

## 범위를 지키는 기준

- 로봇 한 대와 셀 하나를 먼저 완성한다. 여러 셀은 성능 검증 단계에서 늘린다.
- 4축 IK와 정해진 경유점 피킹부터 완성한다. 6축 자세 제어·충돌 회피 경로 계획은 후속 과제다.
- 실물 PLC 없이도 외부 서버와의 실제 통신을 구현한다. 가상 데이터 사용 여부를 명시한다.
- 상세 화면 꾸미기와 차트는 정확한 상태·수량·알람 연결 후 진행한다.
- 대기열로 발생한 정상 대기는 적체 고장과 구분한다.
- 상품 수량, 축 단위, 도구 오프셋, 상태 전이가 맞지 않으면 다음 큰 기능으로 넘어가지 않는다.
- 업체 패키지·샘플·유료 에셋 원본은 공개하지 않는다. 자체 코드·설정·문서의 공개 범위를 확인한다.
